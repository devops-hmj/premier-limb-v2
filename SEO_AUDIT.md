This document maps every URL on the live WordPress site
(`https://premierlimblengthening.com`) to its status in the new Next.js

and supplies hand-written `<title>` + `<meta name="description">` values
for every page so nothing ships with auto-generated meta.

## 1. Executive summary for leadership

| Area | Status | Risk |
|---|---|---|
| Pages built (38 originals) | **27 rendering** · **11 missing** | Inbound Google traffic to missing URLs → 404 |
| URL structure preserved | **No.** All non-home pages moved to `/v2/...` prefix | Every WP URL changes — needs 301s |
| Pages marked `noindex` | **7 of the 8 explicit `metadata` blocks** set `robots: { index: false, follow: false }` | Google can crawl but **will not index** them. **This is the single biggest active SEO bug.** |
| `<title>` tags | All pages have one (auto-derived or hand-written) | OK — improvable |
| `<meta description>` | Hand-written on 8 pages, auto-derived from first paragraph on 30 | Auto descriptions are decent but generic — needs the hand-written values below |
| `sitemap.xml` | Generated by `app/sitemap.ts` — currently lists 22 URLs | Doesn't enumerate the 11 missing pages; if any of them aren't built we still need 301s |
| `robots.txt` | Built. Allows everything except `/api`, `/_next`, `/design-system`. References `sitemap.xml` | Good |
| Schema.org JSON-LD | `MedicalBusiness`, `WebSite`, `Article`, `Physician`, `MedicalProcedure`, `FAQPage`, `BreadcrumbList`, `ItemList` builders exist in `lib/jsonld.ts` | Builders exist; not yet wired into every page |

**Net:** if we publish today, organic traffic drops because (a) most pages
are flagged `noindex`, (b) every inbound link to a non-home URL 404s, and
(c) 11 URLs from the live site have no destination at all.

The fixes are mechanical, not architectural. Section 4 lists them and
this commit lands the critical ones.

## 3. URL strategy (Option A executed)

**Status: ✅ Option A shipped.** Every customer-facing route was physically
moved out of `app/v2/*` to `app/*`. The 23 pages that carry over verbatim
from the legacy WordPress site (16 articles + 7 surgery sub-pages) now
match their original WP URLs 1:1 with zero redirect hops. The "New path"
column in section 2 stays accurate after dropping the `/v2/` prefix.

Single-hop 301s remain in `next.config.mjs` for the three cross-route
renames where the new slug deliberately differs from the legacy WP slug.
**The new slug is the audit's proposed path, NOT brand preference** —
brand wording lives in the UI (nav label, hero, page title); URL slugs
are decided by the live-site audit:

| Legacy WP URL | New URL | UI label | Reason for slug |
|---|---|---|---|
| `/consult/` | `/contact` | Contact | Standard convention |
| `/blog/` | `/journal` | Resources | Audit-proposed slug; brand uses "Resources" in nav/hero, URL stays `/journal` to keep a single 301 hop from legacy `/blog/` |
| `/limb-lengthening-pricing-options/` | `/pricing` | Pricing | Shorter, cleaner |

Plus interim 302s for the 9 not-yet-built pages (5 categories, 3
authors, 1 video) all landing on `/journal` until the per-category and
per-author routes get built (proposed paths in §2d-e).

The previous "Option B" 301 map for per-article and per-surgery-sub
redirects has been deleted: those pages are now direct hits.

A defensive `/v2/:path*` → `/:path*` catch-all stays in `next.config.mjs`
to guard against any cached or pre-launch shared link that still uses
the `/v2/` prefix.

## 4. What this commit fixes

- **Removed `robots: { index: false, follow: false }` from every customer-facing page** (pricing, contact, dr-basmajian, about, journal, articles, your-surgery sub-pages). The only `noindex` left is on `/design-system`, which is correct.
- **Rewrote the eight hardcoded `metadata` blocks** with the SEO-tuned titles and descriptions from section 2.
- **Added a redirects map in `next.config.mjs`** sending every original WordPress URL (sections 2a–2c) to its new home, plus catch-alls for the 11 not-yet-built URLs (category, author, video) pointing at the most relevant existing destination.
- **Expanded `app/sitemap.ts`** to enumerate every built page (articles + service-sub + surfaces), so Google Search Console can crawl the full inventory.

## 5. Open items

1. ✅ **Decide Option A vs. Option B** (URL prefix). Resolved 2026-05-28: Option A executed. Routes moved, redirects cleaned, sitemap reissued at root paths.
2. **Build the 5 category pages, 3 author pages, and 1 video page**, or accept the interim 302s as permanent. If the team plans on continuing to publish, category pages are worth building.
3. **Wire the JSON-LD builders into each page.** `lib/jsonld.ts` exposes `articleSchema`, `physicianSchema`, `medicalProcedureSchema`, `pricingSchema`, `faqPageSchema`, `breadcrumb`, and `collectionPageSchema` but only the site-wide graph is mounted in `app/layout.tsx`. 5. **Confirm the canonical domain.** Everything in `lib/site.ts` and `lib/jsonld.ts` assumes `premierlimblengthening.com`. If the launch domain is different (e.g. a staging subdomain), update `site.domain` before generating the production sitemap.
